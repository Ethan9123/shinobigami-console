# 忍神控制台

面向《忍神 / Shinobigami》团务的本地优先、非官方辅助工具。它把开团准备、角色与秘密、场景巡次、情报、布局和攻击结算集中在一个无需账号的网页里，同时保留 GM 的最终裁定权。

> 本仓库不包含规则书、模组正文、字幕原文或完整忍法资料。使用者仍需合法持有原作资料；导入的立绘、角色卡文本和跑团记录默认只留在当前浏览器及用户主动导出的 JSON 存档中。

## v1.1：场景牌桌与局势神谕

- 场景导演新增“场景牌桌”，每幕自动给出地点、动静、线索与代价四张原创灵感牌；可分别锁定、重抽未锁定牌、单张或整组写入场景笔记，让临场素材始终可见且可操作；
- 情报、感情、回复、战斗与计划五类场景可从牌桌一键切换。卡牌只描述可见局势与开放式问题，不读取角色秘密，也不会自动触发规则效果；
- 新增本地 2D6“局势神谕”：GM 可先选择“不太可能 / 五五开 / 很可能”，再获得有利、附带条件、新入口或明确不利的方向；对子与高张力低点数可能带来异变，但结果只用于主持灵感；
- 镜头账本从已完成场景日志统计每名 PC 的累计场次和占比。聚光灯建议会先照顾本巡未行动者，再优先累计镜头较少的人；
- 交互模式参考开源团务工具的公开设计：Fari 的场景卡与公开/私密分区、COMP/CON 的当前行动聚焦、Iron Fellowship 的主持神谕与共享进度、Obsidian Initiative Tracker 的快速状态反馈、Solo Toolkit 的紧凑进度条。没有复制这些项目的代码、规则文本或美术。

## v1.0：熟练 GM 导演席

- 场景导演首屏升级为“熟练 GM 导演席”，按照「定调 → 聚焦 → 抉择 → 余波」四个节拍带领一场戏，当前该做什么始终在首屏可见；
- 聚光灯建议会优先照顾本巡尚未行动的 PC，并结合剩余生命力、已知情报、人物感情、活跃 NPC 与事件时钟推荐回复、情报、感情、战斗或计划判定，减少熟练玩家霸占镜头、安静玩家长期等待的情况；
- 每个行动都提供可直接朗读的场景开场、面向玩家的开放式问题，以及判定前应公开的成功所得和失败代价；玩家仍决定角色做什么，系统只帮助 GM 把选择说清楚；
- 新增“失败也前进”：失败不会被悄悄改成成功，也不会让剧情停摆；系统会建议以暴露位置、时钟推进、附带条件、NPC 交易或关系介入等剧情代价继续推进，并可一键写入场景笔记；
- 场景张力会综合巡数、场次、环境压力、战斗、到点主持事件和最高事件时钟形成 0–100 读数，帮助 GM 判断应该留白、牵引、施压还是逼近高潮；
- 桌面安全模式只保留主持事件数量，不显示事件内容。导演提示不会读取角色秘密，也不会自动造成伤害、变调或修改判定结果。

## v0.9：开源团务互通桥

- 角色工作台可生成 BCDice 的 ShinobiGami 命令调色板：已习得特技、已装备忍法及代用目标值会转换为 `SG@12#2>=目标值`，并附上 ET / FT / WT / BT / ST / RCT / RTT 命令入口；只引用命令语法，不复制规则表正文，也不把约 40 MB 的完整投骰引擎塞入离线前端；
- 可复制 CCFOLIA 角色剪贴板 JSON：同步姓名、公开角色资料、六分野生命力、布局值与 BCDice 命令；浏览器内的本地立绘不会被编码进剪贴板；
- 可下载 Foundry VTT Shinobigami Actor JSON：转换六分野特技表、特技空隙、生命力、忍法、背景、忍具及角色详情，方便继续在 VTT 中整理；
- 三个出口均在浏览器本地生成。秘密与奥义默认不导出，只有主动勾选后才进入 CCFOLIA 备忘或 Foundry Handout / Finish Item；桌面安全模式会锁死这一开关；
- 兼容结构参考 [BCDice](https://github.com/bcdice/BCDice)（BSD-3-Clause）、[CCFOLIA-Akyou](https://github.com/neotaso/CCFOLIA-Akyou)（MIT）与 [FVTT-Shinobigami-System](https://github.com/ksx0330/FVTT-Shinobigami-System)（MIT）。项目没有复制这些仓库的实现代码，只按公开格式生成用户自己的团务数据。

## v0.8：实战对齐

- 跑团记录台支持中文论坛实录直贴：识别「名字 : 台词」（全角/半角冒号）、`2D6 (2D6) ＞ 8[2,6] ＞ 8` 等骰点回显、ET 感情表 / FT / WT / rtt 表格行、「第X循环，第Y场景」「主持人场景」「后日谈」「尾声」等场景标题、`[閒聊]` 频道前缀、`→` 状态变更行与剧透折叠标记，宣言/使用/登场等行单独归类为动作；
- 角色工作台对齐纸面自动卡：新增「条件」「流仪」与下位流派（如「隐忍-土蜘蛛」按 `-`/`・` 自动拆分），背景清单升级为结构化表格（序号、名称、类别、功绩点、效果，自动小计），纯文本导入同步识别以上字段与背景行；
- 新增秘宝面板：登记、指派持有者与【让渡】操作，转移自动写入团务日志，随存档、撤销与 JSON 迁移一并保存；
- 自动 Replay 工房新增「实战巡回」生成模式：按 导入（每名 PC 一幕）→ 循环 ×（场景表、情报/感情/回复场景）→ 主持人场景 → 高潮多轮战斗（布局、奥义解放与破解、变调）→ 每名 PC 后日谈 的真实团务结构组织正文，全体角色轮流坐上场景玩家位；生成文本可无损送回跑团记录台检索；
- 生成结构只借鉴公开的通用团务流程与骰点格式；仓库与产物仍不含任何规则书、模组正文或跑团实录原文，示例与测试语料均为原创。

## v0.7：自动 Replay 工房

- 读取当前忍务名称与角色的姓名、流派、使命、信念、特技、忍法和奥义，在浏览器本地生成完整跑团 Replay 草稿；
- 以「引子 → 调查 → 受挫 → 假胜利 → 秘密反转 → 高潮 → 余韵」组织张力，短篇、标准与长篇分别生成 5、7、9 幕；
- 支持都市悬疑、学园怪谈、黑色谍战与热血决战四类氛围，以及四种结局和三级戏剧强度；
- 固定种子可复现同一正文，换种子可重演；生成结果带张力曲线、戏剧化 2D6 判定、TXT 导出，并可一键送入跑团记录台继续检索和改稿；
- 角色秘密默认不进入生成内容，只有 GM 主动允许时才会引用；桌面安全模式会强制关闭秘密引用并遮盖已经生成的秘密揭示；
- 生成器不需要 API Key，也不会上传团务资料。自动判定仅服务于故事草稿，不替代实际掷骰、规则效果或 GM 裁定。

## v0.6：角色工作台与跑团记录台

- 角色工作台采用接近纸面自动角色卡的信息密度：本地立绘、玩家/年龄/性别/表之颜/信念/仇敌/功绩点、人物故事、背景、奥义细项、六分野特技矩阵与表格式忍法清单集中显示；
- 纯文本角色卡导入扩展到上述常见字段，并继续识别简繁体/日文特技名；
- 场景导演可导入 UTF-8 的论坛 Log、聊天记录或粘贴文本，按阶段/巡/场景、发言者与关键词建立本地检索索引；
- 任意一条记录可加入当前场景笔记，桌面安全模式会整体遮盖记录，避免共享屏幕时泄露秘密；
- 长记录最多保存前 5000 条，角色立绘会在浏览器内压缩；若浏览器存储空间不足，仍可用 JSON 存档手动保存。

项目不会内置《追忆》或其他官方模组正文。用户导入内容仅用于本人主持与复盘，公开部署产物只包含解析器和原创界面。

## v0.5：第一次忍务

“第一次忍务”是一段原创的单人协力教学流程，让完全没有玩过《忍神》的玩家可以边玩边学，而不是先阅读整本规则：

1. 建立安全约定，并确认随时可暂停或跳过不适内容；
2. 载入一名玩家角色与两名系统 NPC，认识使命、秘密与角色动机；
3. 在教学场景中完成第一次行动描述和 2D6 判定；
4. 经过两巡主要阶段，逐步练习场景、调查、感情与情报；
5. 在高潮阶段按提示完成布局、攻击与结算；
6. 选择结局，并用“星与愿”记录喜欢的瞬间和下次愿望。

流程一次只解释当前需要的概念，并允许随时收起或重新展开说明。为避免关键教学节点因一次失败而停止，本原创剧本会在指定位置使用“失败推进”，让失败产生代价或新局面；这是本剧本的教学与主持技术，**不是《忍神》的官方通则**，也不会改变规则规定的判定结果。

## 其他能力

- 开团公告、PC 分配、角色卡复核与秘密送达检查；
- 场景导演、巡次和行动、主持事件、进度条与团务日志；
- 四节拍 GM 导演席、聚光灯公平提示、判定得失声明、失败推进与动态场景张力；
- 定向感情、非连锁情报共享和桌面安全遮罩；
- 精确 2D6 概率、特技代用、秘密布局、距离与花费检查；
- 按步骤处理命中、宣言窗口、回避、效果和同速延迟结算；
- 纯文字角色卡导入、撤销、本地存储和 JSON 存档迁移；
- BCDice 命令调色板、CCFOLIA 剪贴板角色与 Foundry VTT Actor JSON 导出。

## 本地资料与发布边界

用户提供的规则书和跑团字幕只在本机用于理解规则边界、真实开团流程与新人常见困难。规则书、字幕文件及其原文摘录不会加入仓库、构建产物或发布站点；产品只保存原创界面、流程校验和必要的简短规则提示。

特殊忍法、扩展规则、勘误和剧情冲突仍以所用版本的规则书、官方支持资料及 GM 裁定为准。
