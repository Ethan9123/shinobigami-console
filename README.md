# 忍神控制台

面向《忍神 / Shinobigami》团务的本地优先、非官方辅助工具。它把开团准备、角色与秘密、场景巡次、情报、布局和攻击结算集中在一个无需账号的网页里，同时保留 GM 的最终裁定权。

> 本仓库不包含规则书、模组正文、字幕原文或完整忍法资料。使用者仍需合法持有原作资料；导入的立绘、角色卡文本和跑团记录默认只留在当前浏览器及用户主动导出的 JSON 存档中。

## v1.9.0：组件拆分

本版只重构代码结构，功能与界面保持不变，为下一版的全面三语化和后续新手体验改造打基础。

- 原先 2,402 行的 `ShinobigamiConsole.tsx` 拆为 `app/components/console/` 下约 45 个文件，主文件只剩 68 行：
  - 状态仓库 `store/`；
  - 按领域划分的操作 `actions/`，分为名册、开团准备、战斗、导演、角色台、Replay、教学、存档 8 组；
  - 派生量；
  - 顶栏、导航、角色栏、状态条等外壳 `shell/`；
  - 侧栏 `side/`；
  - 各视图及其子面板 `views/`；
- 需要存档的 25 个会话字段合并为单一 `game` 对象。以前同一份字段清单分散在 7 处（恢复、保存、撤销、导入、教学开局、重置示例团、当前快照），漏改一处就会丢档；现在只剩一份。存档格式、键名与字段顺序逐字节不变，schema 仍为 9，旧存档无需迁移；
- 智能提示抽成纯函数 `app/lib/hints.ts`，可单独测试。与旧实现比对了 4,258 组随机状态，输出一致；
- 18 个下拉框的选项补上显式 `value`（值与原文字相同，行为不变），为界面翻译做准备：翻译显示文字后，写进存档的仍是原来的中文键；
- 页面标题与分享卡片不再写死版本号（此前仍显示「v1.7」）；
- 验证方法：
  - 用 headless Edge 固定随机数和时钟，对 v1.8.0 与本版逐一比对三种语言下 7 个视图的 DOM；
  - 同时比对一段覆盖开团、完整攻击与回避、导演、Replay、角色台、骰娘、教学的脚本流程在每一步的 DOM 和存档；

## v1.8.0：判定正确性

- 「自由」指定特技（审计 #13）：【接近战攻击】【射击战攻击】等忍法在习得时选定指定特技，忍法配置、宣言面板都能直接选；未指定时拒绝宣言、开团门禁给出一键建议；命中与回避判定锚定到选定的特技，不再沿用判定面板上残留的特技，BCDice 调色板与 Foundry 导出同步使用；自定义忍法可选「自由／无」；
- 麻痹自动化：变调栏的「麻痹」每点一次追加一层，随机封锁一个尚未被封的已习得特技并写日志（如“雾隐 麻痹：封锁《毒术》（第 2/6 层）”），按钮显示「麻痹×n」；被封特技在特技表上划掉，判定面板和 BCDice 调色板会自动剔除并改按代用计算；「全部解除（身体操术判定成功）」一键清空；旧存档只有「麻痹」标签时提示补抽，不在载入时乱猜；
- 【木莲】【魔界工学】：两条装备忍法加入忍法配置，习得后特技表分别上下连通、左右连通，代用距离自动走更短的一侧（判定面板注明“经木莲/魔界工学连通”）；空隙控件新增第 6 个按钮「器术左侧（外）」，Foundry 导出同步写入；
- 得意分野：六大流派（及其下位流派）会检查得意分野特技数和两侧空隙，不一致时开团门禁给出提醒（只提醒、不阻塞），角色工作台可点「按得意分野涂黑空隙」一键涂好；示例角色月影补涂了器术/体术空隙、补齐 3 个体术特技，代用目标值随之降低 1；
- 逆止：战斗中（攻击处理～回合结束）陷入逆止的角色进行行为判定时自动失败（达成值 0、成功率显示 0%），奥义或写明可在逆止中使用的效果可勾选豁免；完成场景、开始新巡时与新回合一样清除逆止、布局、已用花费和已用忍法，战斗外残留的逆止标签只提示、不影响判定；
- 判定面板复位：宣言、进入回避、换行动者、新回合与切换角色时，代用选择、修正、骰池和支援花费全部复位，不会把上一个人的“远距代用”或 +1 带到下一次判定；宣言带花费的支援忍法时，按其花费自动抬高本次判定的大失败值；
- 布局值 0：布局栏新增「违规→0」，布局 0 行动排最后、大失败值为 2，被布局 1 以上的角色攻击时无视距离；公开后改为 0 或有人脱落／重新参战时，行动指针继续跟住当前行动者，不会跳过下一位；
- 攻击时机：攻击忍法只能在自己行动时宣言、一回合一次，追加攻击等特例可由 GM 覆盖；指定特技为「无」的自定义忍法宣言后跳过命中判定，直接进入宣言窗口；
- 导入与存档加固：导入的角色卡不再含被封特技时一并解除「麻痹」标签；流派简称「御斋学园」与日文／繁体写法、忍法【木蓮】【魔界工學】都能识别；存档里畸形的自定义忍法会被丢弃或校正，不再导致界面白屏；
- BCDice 调色板：失去生命力分野或被麻痹封锁的特技不再输出目标值 12，而是写出最近可用特技的代用目标值（如「潜伏术→火术」）；
- 名称修正：术语表「共鸣／猜疑」英文改为官方 Empathy／Mistrust；阶级下拉补「下忍头」并提供「草」；导入能识别日文忍法名 接近戦攻撃・射撃戦攻撃・鎌鼬，以及“接近战攻击（刀术）”这类写明指定特技的写法；
- 存档升级到 schema 9：旧档的「自由」忍法不猜测特技，留待补选；新增 `paralyzedSkills`（麻痹封锁的特技）与 `outerGapClosed`（器术左侧外空隙），旧档分别为空与未涂黑；本地角色库保留外空隙、清空麻痹等临时状态。

## 新手：从没跑过忍神也能开团

如果你手里有规则书却迟迟不敢开第一团，建议按这个顺序用它：

1. `npm install && npm run dev` 打开页面，直接点「第一次忍务」——一段边玩边学的单人教学（原创剧本《雨夜零号线》），把使命、秘密、2D6 判定、感情、布局和高潮战斗各练一遍，全程不需要先读完规则书；
2. 正式开团前走一遍「开团准备」：填公告、把每位 PC 的使命/秘密录进手册，就绪检查会在秘密漏发、角色卡没复核时拦住你——新手 GM 最常见的开团事故基本都在这层被挡掉；
3. 玩家的纯文字自动角色卡直接粘贴进「角色工作台」导入，特技/忍法/背景清单自动识别（兼容简繁体与日文特技名）；
4. 跑团中把「场景导演」当 GM 副驾驶：聚光灯建议告诉你该给谁镜头，可朗读开场帮你救冷场，判定前公开的成功/失败后果让玩家敢掷骰，「失败也前进」保证失败不会卡死剧情；
5. 判定与战斗交给「战斗控制台」：精确成功率、代用特技目标值、战斗中大失败线＝布局值、五步攻击结算流程都会自动算好——规则苦手不用再来回翻书；
6. 团后把论坛 Log 或聊天记录粘进「跑团记录台」做检索，或用「Replay 工房」生成一份可改稿的戏剧化 Replay 存档留念。

规则速查提示只覆盖通用机制概念；特技表数值、忍法效果与扩展规则请对照你持有的规则书，最终裁定永远在 GM。

- 情报、感情、回复、战斗与计划五类场景可从牌桌一键切换。卡牌只描述可见局势与开放式问题，不读取角色秘密，也不会自动触发规则效果；
- 新增本地 2D6“局势神谕”：GM 可先选择“不太可能 / 五五开 / 很可能”，再获得有利、附带条件、新入口或明确不利的方向；对子与高张力低点数可能带来异变，但结果只用于主持灵感；
- 镜头账本从已完成场景日志统计每名 PC 的累计场次和占比。聚光灯建议会先照顾本巡未行动者，再优先累计镜头较少的人；
- 交互模式参考开源团务工具的公开设计：Fari 的场景卡与公开/私密分区、COMP/CON 的当前行动聚焦、Iron Fellowship 的主持神谕与共享进度、Obsidian Initiative Tracker 的快速状态反馈、Solo Toolkit 的紧凑进度条。没有复制这些项目的代码、规则文本或美术。

## v1.0：熟练 GM 导演席

- 场景导演首屏升级为“熟练 GM 导演席”，按照「定调 → 聚焦 → 抉择 → 余波」四个节拍带领一场戏，当前该做什么始终在首屏可见；
- 聚光灯建议会优先照顾本巡尚未行动的 PC，并结合剩余生命力、已知情报、人物感情、活跃 NPC 与事件时钟推荐回复、情报、感情、战斗或计划判定，减少熟练玩家霸占镜头、安静玩家长期等待的情况；
- 每个行动都提供可直接朗读的场景开场、面向玩家的开放式问题，以及判定前应公开的成功所得和失败代价；玩家仍决定角色做什么，系统只帮助 GM 把选择说清楚；
- 新增“失败也前进”：失败不会被悄悄改成成功，也不会让剧情停摆；系统会建议以暴露位置、时钟推进、附带条件、NPC 交易或关系介入等剧情代价继续推进，并可一键写入场景笔记；
- 场景张力会综合巡数、场次、环境压力、战斗、到点主持事件和最高事件时钟形成 0–100 读数，帮助 GM 判断应该留白、牵引、施压还是逼近高潮；
- 桌面安全模式只保留主持事件数量，不显示事件内容。导演提示不会读取角色秘密，也不会自动造成伤害、变调或修改判定结果。

## v0.9：开源团务互通桥

- 角色工作台可生成 BCDice 的 ShinobiGami 命令调色板：已习得特技、已装备忍法及代用目标值会转换为 `SG@12#2>=目标值`，并附上 ET / FT / WT / BT / ST / RCT / RTT 命令入口；只引用命令语法，不复制规则表正文，也不把约 40 MB 的完整投骰引擎塞入离线前端；
- 可复制 CCFOLIA 角色剪贴板 JSON：同步姓名、公开角色资料、六分野生命力、布局值与 BCDice 命令；浏览器内的本地立绘不会被编码进剪贴板；
- 可下载 Foundry VTT Shinobigami Actor JSON：转换六分野特技表、特技空隙、生命力、忍法、背景、忍具及角色详情，方便继续在 VTT 中整理；
- 三个出口均在浏览器本地生成。秘密与奥义默认不导出，只有主动勾选后才进入 CCFOLIA 备忘或 Foundry Handout / Finish Item；桌面安全模式会锁死这一开关；
- 兼容结构参考 [BCDice](https://github.com/bcdice/BCDice)（BSD-3-Clause）、[CCFOLIA-Akyou](https://github.com/neotaso/CCFOLIA-Akyou)（MIT）与 [FVTT-Shinobigami-System](https://github.com/ksx0330/FVTT-Shinobigami-System)（MIT）。项目没有复制这些仓库的实现代码，只按公开格式生成用户自己的团务数据。

## v0.8：实战对齐

- 跑团记录台支持中文论坛实录直贴：识别「名字 : 台词」（全角/半角冒号）、`2D6 (2D6) ＞ 8[2,6] ＞ 8` 等骰点回显、ET 感情表 / FT / WT / rtt 表格行、「第X循环，第Y场景」「主持人场景」「后日谈」「尾声」等场景标题、`[閒聊]` 频道前缀、`→` 状态变更行与剧透折叠标记，宣言/使用/登场等行单独归类为动作；
- 角色工作台对齐纸面自动卡：新增「条件」「流仪」与下位流派（如「隐忍-土蜘蛛」按 `-`/`・` 自动拆分），背景清单升级为结构化表格（序号、名称、类别、功绩点、效果，自动小计），纯文本导入同步识别以上字段与背景行；
- 新增秘宝面板：登记、指派持有者与【让渡】操作，转移自动写入团务日志，随存档、撤销与 JSON 迁移一并保存；
- 自动 Replay 工房新增「实战巡回」生成模式：按 导入（每名 PC 一幕）→ 循环 ×（场景表、情报/感情/回复场景）→ 主持人场景 → 高潮多轮战斗（布局、奥义解放与破解、变调）→ 每名 PC 后日谈 的真实团务结构组织正文，全体角色轮流坐上场景玩家位；生成文本可无损送回跑团记录台检索；
- 生成结构只借鉴公开的通用团务流程与骰点格式；仓库与产物仍不含任何规则书、模组正文或跑团实录原文，示例与测试语料均为原创。

## v0.7：自动 Replay 工房

- 读取当前忍务名称与角色的姓名、流派、使命、信念、特技、忍法和奥义，在浏览器本地生成完整跑团 Replay 草稿；
- 以「引子 → 调查 → 受挫 → 假胜利 → 秘密反转 → 高潮 → 余韵」组织张力，短篇、标准与长篇分别生成 5、7、9 幕；
- 支持都市悬疑、学园怪谈、黑色谍战与热血决战四类氛围，以及四种结局和三级戏剧强度；
- 固定种子可复现同一正文，换种子可重演；生成结果带张力曲线、戏剧化 2D6 判定、TXT 导出，并可一键送入跑团记录台继续检索和改稿；
- 角色秘密默认不进入生成内容，只有 GM 主动允许时才会引用；桌面安全模式会强制关闭秘密引用并遮盖已经生成的秘密揭示；
- 生成器不需要 API Key，也不会上传团务资料。自动判定仅服务于故事草稿，不替代实际掷骰、规则效果或 GM 裁定。

## v0.6：角色工作台与跑团记录台

- 角色工作台采用接近纸面自动角色卡的信息密度：本地立绘、玩家/年龄/性别/表之颜/信念/仇敌/功绩点、人物故事、背景、奥义细项、六分野特技矩阵与表格式忍法清单集中显示；
- 纯文本角色卡导入扩展到上述常见字段，并继续识别简繁体/日文特技名；
- 场景导演可导入 UTF-8 的论坛 Log、聊天记录或粘贴文本，按阶段/巡/场景、发言者与关键词建立本地检索索引；
- 任意一条记录可加入当前场景笔记，桌面安全模式会整体遮盖记录，避免共享屏幕时泄露秘密；
- 长记录最多保存前 5000 条，角色立绘会在浏览器内压缩；若浏览器存储空间不足，仍可用 JSON 存档手动保存。

项目不会内置任何官方模组的名称或正文。用户导入内容仅用于本人主持与复盘，公开部署产物只包含解析器和原创界面。

## v0.5：第一次忍务

“第一次忍务”是一段原创的单人协力教学流程，让完全没有玩过《忍神》的玩家可以边玩边学，而不是先阅读整本规则：

1. 建立安全约定，并确认随时可暂停或跳过不适内容；
2. 载入一名玩家角色与两名系统 NPC，认识使命、秘密与角色动机；
3. 在教学场景中完成第一次行动描述和 2D6 判定；
4. 经过两巡主要阶段，逐步练习场景、调查、感情与情报；
5. 在高潮阶段按提示完成布局、攻击与结算；
6. 选择结局，并用“星与愿”记录喜欢的瞬间和下次愿望。

流程一次只解释当前需要的概念，并允许随时收起或重新展开说明。为避免关键教学节点因一次失败而停止，本原创剧本会在指定位置使用“失败推进”，让失败产生代价或新局面；这是本剧本的教学与主持技术，**不是《忍神》的官方通则**，也不会改变规则规定的判定结果。

## 代码结构

- `app/lib/`：规则、会话、教学、骰娘、导演、Replay 等纯逻辑模块。多数可以独立转译测试，因此除 `import type` 外不引用项目内其他文件；
- `app/components/ShinobigamiConsole.tsx`：入口，负责组装控制器并切换视图；
- `app/components/console/`：
  - `store/useGameStore.ts`：唯一持久化的会话状态 `game`，以及本地保存、撤销、导入导出；
  - `useConsoleUi.ts`：各面板的临时输入状态；
  - `useConsoleDerived.ts`：派生量；
  - `actions/*.ts`：按领域划分的操作；
  - `useConsoleController.ts`：把以上几部分组合后通过 `ConsoleContext` 提供给各组件；
  - `shell/`、`side/`、`views/`：各块界面，组件用 `useConsole()` 或 `useSelectedConsole()` 取用状态和操作；
- `tests/`：`node --test` 单元测试。`rendered-html.test.mjs` 会检查界面源码里的关键功能入口。

## 使用与检查

```bash
npm install
npm run dev
```

```bash
npm test            # 单元测试（直接转译源码，无需先构建）
npm run lint        # ESLint，零告警
npm run typecheck   # tsc --noEmit
npm run check       # lint + typecheck + test
npm run verify      # check + vinext 构建 + GitHub Pages 构建
```

提交 PR 后，GitHub Actions 的 `CI` 会跑同样的检查与两种构建，并报告 Pages 入口包体积；也可在本地构建后用 `npm run bundle:report` 查看。

## 部署

- GitHub Pages：`npm run build:pages` 生成纯前端版本，推送到 `main` 后由 GitHub Actions 发布到 `https://ethan9123.github.io/shinobigami-console/`；
- Cloudflare Workers：`npm run deploy:cloudflare` 会先执行 vinext 生产构建，再通过根目录 `wrangler.jsonc` 发布完整的 Worker 版本。

团务数据默认只保存在当前浏览器。本地 JSON 可能包含秘密、奥义和主持信息，请按敏感文件保管；“桌面安全”是共享屏幕遮罩，不等同于多人权限系统。
